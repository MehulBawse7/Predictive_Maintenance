# MachinaSense

**Explainable fault screening for industrial chillers**

MachinaSense is a software prototype that analyzes chiller sensor measurements,
estimates fault-related scores, ranks attention candidates, and provides SHAP
explanations. It is intended to help maintenance teams prioritize inspections.
It does not replace a qualified technician or confirm that equipment has failed.

## How it works

- Accepts 17 chiller input measurements and produces 26 named model outputs.
- Uses a saved TensorFlow/Keras multilayer perceptron (MLP) and the fitted
  StandardScaler from training. The scaler must be applied in the same input
  column order recorded in `model_exports/model_metadata.json`.
- Provides rule-based ranking and SHAP explainability through the backend
  package in `website_backend_bundle.zip`.
- The backend supports a single timestamped reading or a CSV time series with
  one `timestamp` column and all 17 model inputs. It scores each row
  independently; it is not a temporal forecasting model.

## Important interpretation limits

The training targets are synthetic scores generated by a Mamdani fuzzy expert
system. They are not observed failures from operating chillers, and model
scores are not calibrated real-world failure probabilities. Current evaluation
measures how well the MLP reproduces those fuzzy-system labels; it does not
establish field performance or warning lead time.

The supplied expert rules produce four indistinguishable output pairs:

- Condenser valve / filter
- Condenser coil / refrigerant leak
- Evaporator liquid leak / valve
- Compressor contactor / oil loss

The interface should report these as general subsystem candidates when the
specific member cannot be distinguished. The source rules do not contain
approved, component-specific repair procedures; recommendations should direct
users to inspection and qualified maintenance review.

The MLP has a linear output layer and can produce scores outside the expert
system's `[0, 1]` range. The backend marks such assessments incomplete rather
than clipping the scores or presenting them as valid probabilities.

## Threshold status

The project has selected a strict `> 0.5` attention threshold for the intended
website behavior. **The current backend package still implements `> 0.4`**;
update the backend rule and evaluate the selected threshold on a fresh,
separately reserved synthetic test set before describing `> 0.5` as active or
validated. The parent/subsystem gating rule must use the same active threshold.

## Evaluation available

On a separately generated 500-row synthetic check against fuzzy-system labels,
the saved MLP achieved mean R² 0.8588, MAE 0.0369, and RMSE 0.0631 for the
continuous outputs. At the tested `> 0.4` cutoff, binary agreement was 0.9622,
with micro precision 0.9732, recall 0.9127, and F1 0.9420. These figures measure
agreement with the synthetic expert system, not real-world fault detection.
The 30 hand-designed scenarios are a small sanity check and have already been
used during model evaluation; they are not a fresh blind test set.

## Website integration

The planned website stack is React + Vite for the frontend and Python + FastAPI
for the backend. The database choice is pending. The ready-to-share backend
package is `website_backend_bundle.zip`; its English integration guide is
`website_backend_package/README_FOR_WEBSITE_DEVELOPER_EN.md`.

The package contains the saved MLP, scaler, metadata, rule engine, prediction
service, and SHAP support data. It does not contain the website UI. The web
application should load the backend once, accept one reading or timestamped
CSV data, show incomplete assessments clearly, and calculate local SHAP only
when a user requests an explanation.

## Backend package setup

Extract `website_backend_bundle.zip` and run these commands from the extracted
folder using a Python version with TensorFlow/Keras compatible with the saved
model:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements_backend.txt
```

The package exposes `ChillerBackend` in `chiller_backend.py`. See
`README_FOR_WEBSITE_DEVELOPER_EN.md` in the package for the prediction and SHAP
method contracts. No model retraining is needed for inference.
